## Obsidianへの保存

執筆後、コピー・ダウンロードの横の「Obsidian」を押します。初回だけVault名（またはVault ID）と、任意のVault内フォルダーを設定します。「設定して保存」以降、通常の文章は1クリックで渡せます。「設定」から保存先の変更と起動テストができます。設定は `freewriting-obsidian-v1` としてこのブラウザーのlocalStorageに保存します。保存できない環境ではページを閉じるまでの設定となり、その旨を表示します。

Obsidianのインストールと、保存先VaultをObsidianで一度開いておくことが必要です。起動テストは `obsidian://open` で入力中のVaultを開く操作です。ノートは作成せず、設定も保存しません。ブラウザーに確認が出た場合はObsidianの起動を許可してください。

### 保存仕様

- 標準の `obsidian://new?vault=...&file=...&content=...` を使用します。追加のObsidianプラグインやサーバーは不要です。本文は加工せずMarkdownに渡します。
- 各パラメーターを `encodeURIComponent` で個別にエンコードし、日本語、改行、空白、絵文字、`&`・`#`・`+`・`%`などを保持します。
- ファイル名は `FreeWriting-YYYY-MM-DD_HH-mm-ss-SSS-<128bitランダムID>.md` です。日時は執筆開始時のローカル日時です。保存操作ごとに新しいIDを生成し、連続クリックは1.2秒間抑止します。既存ファイルの検索はできないため重複不存在は保証できませんが、上書き・追記パラメーターは送りません。「もう一度Obsidianを開く」は同じ保存先を再利用します。受け取り側の動作によっては再試行で別ノートが増える場合があります。
- フォルダーはVaultからの相対パスです。空欄はVault直下です。絶対パス、`..`、空の階層、一般的に無効な名前や記号は拒否します。
- エンコード後のURIが1,800文字を超える場合、長文用ダイアログに切り替えます。これは環境差を避ける保守的なアプリ内の目安で、OS・ブラウザーの公式上限ではありません。短いURIでも環境によって開けない場合があります。
- 長文は「1. 本文をコピー」の成功後に「2. Obsidianを開く」を表示し、`clipboard=true` の短いURIで渡します。クリップボードへのコピーと起動を別のクリックにして、コピー許可待ちによる起動失敗を避けます。開くまでは別の内容をコピーしないでください。再試行時も再コピーします。
- コピー拒否、Clipboard API非対応、起動不可の場合はMarkdownのダウンロードを利用できます。保存先自体が長すぎて短いURIにも収まらない場合は、Vault IDや短いフォルダー名への変更、またはダウンロードを案内します。既存のコピー・TXTダウンロードも利用できます。
- 起動と保存完了をブラウザーから確実に検出することはできません。タイムアウト、ウィンドウの非表示化などを成功判定には使わず、「起動を依頼しました」と表示します。本文は削除・リセットしません。保存されたかはObsidian側で確認してください。

公式仕様: [Obsidian URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)

### 検証

依存パッケージなしで次を実行できます（Node.js 20以降）。

```sh
node --test
```

ブラウザー側のJavaScriptは `app.js` の1エントリーで完結します。BunのHTMLバンドルでもファイル間の暗黙のグローバル共有に依存しない構成です。ブラウザーのエントリーにはCommonJSの `module.exports` を置かず、テスト側で検証する関数を読み込みます。Bunを使う場合は `bun build ./index.html --outdir ./dist` で生成したページについても起動・設定・保存操作を確認してください。

実機での確認項目:

1. HTTPSのサイトで執筆を終え、初回設定のVault名・任意フォルダーを指定して保存する。
2. ブラウザーの起動確認を許可し、日本語・改行・絵文字・記号を含む本文がそのまま届くことを確認する。
3. 設定の起動テスト、保存先変更、再読み込み後の設定復元を確認する。
4. 同じ日時の保存や再試行でも、既存ノートが上書きされないことを確認する。
5. 長文でコピー→起動の順に渡し、全文が届くこと、再試行で再コピーになることを確認する。
6. コピー拒否・起動キャンセル・Obsidian未インストール・存在しないVault名でも本文が残り、Markdownをダウンロードできることを確認する。

自動テストで生成URIと画面側の処理は検証できますが、OSのプロトコル登録、ブラウザーの許可ダイアログ、Obsidianでの実際の作成は別途実機確認が必要です。
