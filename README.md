## Obsidianへの保存

執筆後、コピー・ダウンロードの横のObsidianアイコンを押します。初回だけVault名（またはVault ID）と、任意のVault内フォルダーを設定します。「設定して保存」以降、長文も含めて1クリックで渡せます。隣の設定アイコンから保存先の変更と起動テストができます。アイコンには操作名のツールチップと読み上げ用ラベルを付けています。設定は `freewriting-obsidian-v1` としてこのブラウザーのlocalStorageに保存します。保存できない環境ではページを閉じるまでの設定となり、その旨を表示します。

Obsidianのインストールと、保存先VaultをObsidianで一度開いておくことが必要です。起動テストは `obsidian://open` で入力中のVaultを開く操作です。ノートは作成せず、設定も保存しません。ブラウザーに確認が出た場合はObsidianの起動を許可してください。

### 保存仕様

- 標準の `obsidian://new?vault=...&file=...&content=...` を使用します。追加のObsidianプラグインやサーバーは不要です。本文は加工せずMarkdownに渡します。
- 各パラメーターを `encodeURIComponent` で個別にエンコードし、日本語、改行、空白、絵文字、`&`・`#`・`+`・`%`などを保持します。
- ファイル名は `FreeWriting-YYYY-MM-DD.md` です。執筆開始時のローカル日付だけを使い、時刻・ミリ秒・ランダムIDは付けません。同名ファイルへの対応はObsidian側の新規作成処理に任せ、上書き・追記パラメーターは送りません。連続クリックは1.2秒間抑止します。再試行も同じ候補名を送り、Obsidian側で別ノートが増える場合があります。同日の複数保存は実機確認の対象です。
- フォルダーはVaultからの相対パスです。空欄はVault直下です。絶対パス、`..`、空の階層、一般的に無効な名前や記号は拒否します。
- エンコード後のURIが1,800文字を超える場合、本文を自動でクリップボードにコピーし、コピー成功後すぐに `clipboard=true` の短いURIでObsidianを開きます。中間ダイアログや追加のクリックは不要です。これは環境差を避ける保守的なアプリ内の目安で、OS・ブラウザーの公式上限ではありません。
- 長文の保存操作はクリップボードを置き換えます。保存されるまでは別の内容をコピーしないでください。再度保存した場合も本文をコピーし直します。コピー待ちの間は連続操作を抑止し、その間にセッションや保存先が変わった場合は古い起動処理を中止します。
- コピー拒否やClipboard API非対応の場合は、本文を残して短いエラーを表示し、古いクリップボードの内容でノートを作りません。保存先自体が長すぎる場合は設定変更を案内します。既存のコピー・TXTダウンロードも利用できます。ブラウザーやOSが表示するコピー・外部アプリ起動の許可確認は、アプリ側では省略できません。
- 起動の依頼後、Obsidianアイコンを1.2秒だけチェックマークに切り替えてから戻します。左下の再試行・ダウンロード操作や、通常時の案内文は表示しません。チェックは起動依頼の操作を示し、Obsidianでの保存完了を保証するものではありません。本文は削除・リセットしません。設定の記憶失敗などのエラーだけは文章で表示します。

公式仕様: [Obsidian URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)

### 検証

依存パッケージなしで次を実行できます（Node.js 20以降）。

```sh
node --test
```

ブラウザー側のJavaScriptは `app.js` の1エントリーで完結します。BunのHTMLバンドルでもファイル間の暗黙のグローバル共有に依存しない構成です。ブラウザーのエントリーにはCommonJSの `module.exports` を置かず、テスト側で検証する関数を読み込みます。Bunを使う場合は `bun build ./index.html --outdir ./dist` で生成したページについても起動・設定・保存操作を確認してください。

実機での確認項目:

1. HTTPSのサイトで執筆を終え、初回設定のVault名・任意フォルダーを指定して保存する。
2. ブラウザーの起動確認を許可し、日本語・改行・絵文字・記号を含む本文がそのまま届くことを確認する。
3. 設定の起動テスト、保存先変更、再読み込み後の設定復元を確認する。
4. 同日中に複数回保存し、同名ノートがある場合も別のノートとして作られ、既存ノートが上書きされないことを確認する。
5. 長文でもアイコン1回でコピー→起動が進み、中間ダイアログが出ないこと、全文が届くことを確認する。
6. コピー拒否・起動キャンセル・Obsidian未インストール・存在しないVault名でも本文が残り、既存のTXT保存が利用できることを確認する。

自動テストで生成URIと画面側の処理は検証できますが、OSのプロトコル登録、ブラウザーの許可ダイアログ、Obsidianでの実際の作成は別途実機確認が必要です。
